what's actually different here

Bootstrap DNS, not a hosts-only guess

A small plain-IP bootstrap resolver handles resolving the remote/direct DNS servers' own hostnames by default — so any custom DoH provider works, not just ones hardcoded into a hosts table. The static hosts table still exists and is used automatically as a faster override, but only for the handful of well-known providers it actually contains.

Real self-loop protection

The TUN interface's own address is explicitly rejected-and-dropped in route.rules, matched per single address rather than by CIDR prefix — on Linux, sing-tun registers a derived address in that same prefix range with systemd-resolved as a DNS upstream, so a prefix-wide match would silently break system DNS. This client's own traffic is also always excluded by process name automatically — no manual path to configure.

No forced TLS fingerprint

If your vless:// link doesn't specify fp=, no utls block is added at all — matching v2rayN's own behavior, which never fakes a fingerprint you didn't ask for. Want one anyway? The "Force a fingerprint" option under TLS fingerprint adds it explicitly, clearly as this tool's own addition on top.

Fail closed, not fail open

route.final is proxy. Anything not explicitly matched to direct — private IPs and (optionally) the geosite-private set — goes through the tunnel. If the tunnel is down, it fails, it doesn't silently fall back to your real IP.

Client-side only — your links, UUIDs, and keys are never transmitted anywhere. Verify with sing-box check -c config.json before relying on it. Interface name is fixed to singbox_tun, MTU to 9000, and log level to warn — sensible defaults nobody typically needs to change.
